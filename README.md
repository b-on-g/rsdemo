# $bog_rsdemo

Список задач на Rust поверх ядра `$mol_wire` из `mol/wire/wire.rs`. Нужен сборщик с поддержкой `.rs`, он лежит в ветке `rust` форка [Dev-cmyser/mam_mol](https://github.com/Dev-cmyser/mam_mol/tree/rust).

```sh
npx mam mol/build
node mol/build/-/node.js bog/rsdemo
bog/rsdemo/-/native
```

Сборка кладёт в `-/` нативный бинарь `native`, прогоняет `cargo test` и собирает `web.wasm`. Для wasm нужен `rustup target add wasm32-unknown-unknown`.

## В браузере

`index.html` открывает `$bog_rsdemo`, обычный вид на $mol. Он грузит `web.wasm` через `$mol_wire_rs`, а в `auto()` запускает Rust. Внутри Rust `Auto` собирает состояние в JSON и отдаёт его импортом `render`, а тот кладёт его в атом `state`. Кнопки зовут экспорты `bog_rsdemo_add`, `_done`, `_shelve`, `_remove`. Rust пересчитывается по микротаске и снова зовёт `render`. В шапке выводится число живых узлов арены.

```sh
sleep 100000 | MAM_BUILD_SERVER_PORT=9091 node mol/build/-/node.js
```

Страница открывается по адресу `http://localhost:9091/bog/rsdemo/-/test.html`.

## Владение как в моле

Атом владеет только своим значением целиком, внутрь `Vec`, кортежей и словарей он не заглядывает. Владеет тот, кто поймал объект первым, и владение потом никуда не переходит. Значение сменилось, и старый объект уничтожается. У атома не осталось подписчиков, и в конце тика он уходит вместе со своим объектом.

Поэтому списки `tasks` и `archive` хранят id, а объект задачи отдаёт фабрика `task(id)`. Задача живёт, пока на `task(id)` подписан хоть один вид: `board` или `shelf`. Перенос в архив меняет только список id, объект остаётся тем же. Когда id не осталось ни в одном списке, задача умирает на ближайшем `sync()`.

Данные лежат в `Store` по id, а `Task` только линза над ним с собственным кэшем `label`. Если фасад умер без подписчиков и потом создан заново, `title` и `done` берутся из стора.

## solid

Как и в моле, значение, положенное через put, держится, пока у атома не пропал последний подписчик. После этого атом в конце тика сбрасывается. Корневое состояние зовёт в теле свойства `solid()`, аналог `$mol_wire_solid()`, и тогда атом не убирается вовсе. Так помечены стор, счётчик id и списки `tasks` и `archive`. Освобождается такой атом только вместе со своим объектом, например когда уничтожен `Root`.
